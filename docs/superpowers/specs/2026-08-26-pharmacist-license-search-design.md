# ค้นเลขที่ใบอนุญาต ภ. จากชื่อ-นามสกุลเภสัชกร

วันที่ 26 สิงหาคม 2569 (2026-08-26)

## ปัญหา

หน้าบันทึกการตรวจ (`web/public/form.html`) มีช่อง "ใบอนุญาตเป็นผู้ประกอบวิชาชีพ
เภสัชกรรม เลขที่ ภ." (`pharmacistLicenseNo`) ที่ต้องกรอกด้วยมือ ข้อมูลจากพอร์ทัล
อย. ให้ชื่อเภสัชกรผู้มีหน้าที่ปฏิบัติการมา แต่ไม่ให้เลขที่ใบอนุญาตวิชาชีพ
ผู้ตรวจจึงต้องเปิดเว็บสภาเภสัชกรรมอีกแท็บเพื่อค้นเลขนั้นทุกครั้ง

## เป้าหมาย

เพิ่มช่องค้นหาชื่อ/นามสกุลเภสัชกรไว้ใน sidebar ของหน้าค้นร้านยา และไว้ในหน้าบันทึก
การตรวจ ผลลัพธ์แสดงเลขที่ใบอนุญาตพร้อมปุ่มคัดลอก ผู้ตรวจไม่ต้องออกจากหน้าเดิม

**ไม่อยู่ในขอบเขต:** การเติมค่าลงฟอร์มอัตโนมัติ — ผลลัพธ์แสดงอย่างเดียว ผู้ใช้
คัดลอกไปกรอกเอง และไม่รองรับการค้นด้วยเลขที่ใบอนุญาต (ผู้ใช้มีเลขอยู่แล้วก็ไม่ต้องค้น)

## ต้นทางข้อมูล

เว็บสภาเภสัชกรรมมีฟอร์มค้นรายชื่อผู้ประกอบวิชาชีพอยู่หน้าแรก ตรวจสอบพฤติกรรมจริง
แล้ว (26 ส.ค. 2569) ได้ดังนี้

- ปลายทาง: `POST https://www.pharmacycouncil.org/index.php?option=com_pharmacist_list`
- `Content-Type: application/x-www-form-urlencoded`, เข้ารหัส UTF-8
- ฟิลด์: `txtfind_type` (`1` = เลขที่ใบอนุญาต, `2` = ชื่อ, `3` = นามสกุล) และ
  `txtfind_id` = คำค้น
- ตอบกลับเป็นหน้า HTML เต็มหน้า (~70–110 KB) ตารางผลลัพธ์คือตารางเดียวในหน้า
  ที่มี `bordercolor="#66CC66"`

คอลัมน์ที่ได้เมื่อค้นด้วยชื่อหรือนามสกุล: ลำดับ, ชื่อผู้ประกอบวิชาชีพเภสัชกรรม
(มีคำนำหน้า `ภก.`/`ภญ.` และอาจมีบรรทัดหมายเหตุต่อท้าย), เลขที่ใบอนุญาต, สถานะ,
ใบอนุญาตหมดอายุ — การค้นด้วยเลขที่ใบอนุญาตให้คอลัมน์ที่อยู่และรูปถ่ายเพิ่ม แต่เรา
ไม่ใช้โหมดนั้น

ข้อจำกัดที่มีผลต่อการออกแบบ

- **จับคู่แบบตรงตัวเท่านั้น** ไม่มี prefix ไม่มี partial — "สมชา" ไม่เจอ "สมชาย"
  และ "ใจ" ไม่เจอ "ใจดี" ต้องสะกดครบทุกตัวอักษรรวมวรรณยุกต์
- **ค้นได้ทีละฟิลด์** ชื่อ หรือ นามสกุล ไม่ใช่พร้อมกัน
- **ไม่มีการแบ่งหน้า** ผลทั้งหมดมาในครั้งเดียว ("สมชาย" คืน 71 แถว)
- ไม่พบรายการ ตารางจะมีแถวเดียวข้อความ "ไม่พบรายการ"

## สถาปัตยกรรม

สามชั้น ตามโครงเดิมของแอป

1. **`src/pharmacist.js`** — โมดูลใหม่ ยิงต้นทาง แปลง HTML เป็น JSON และแคชผล
   วางคู่กับ `src/scraper.js` และใช้รูปแบบเดียวกัน (`ScrapeError`, LRU cache)
2. **`src/server.js`** — เพิ่ม route หนึ่งเส้น ใช้ error handler เดิม
3. **`web/public/pharmacist-search.js`** — custom element `<pharmacist-search>`
   เขียนด้วย vanilla JS ชุดเดียว ใช้ได้ทั้งใน React sidebar และใน `form.html`
   ที่เป็น HTML ล้วน

เลือก custom element เพราะ `form.html` ไม่มี build step และถูก Puppeteer โหลดทุก
ครั้งที่ render PDF — การ bundle React เข้าไปทำให้หน้านั้นหนักขึ้นโดยไม่ได้อะไร
ส่วนการเขียน component สองชุด (React ชุดหนึ่ง vanilla อีกชุด) แปลว่าแก้บั๊กสองที่

component ไม่ใช้ shadow DOM จึงกิน design token และคลาสควบคุมจาก
`web/public/theme.css` ได้ตรง ๆ ซึ่งทั้งสองหน้าโหลดไฟล์นั้นอยู่แล้ว

## Backend

### สัญญา API

```
GET /api/pharmacist?firstName=<ชื่อ>&lastName=<นามสกุล>
```

ต้องส่งมาอย่างน้อยหนึ่งพารามิเตอร์ ถ้าว่างทั้งคู่ตอบ `400` รหัส `MISSING_QUERY`

ตรรกะการยิงต้นทาง

| ที่ผู้ใช้กรอก | คำขอไปต้นทาง | กลุ่มผลลัพธ์ที่ได้ |
| --- | --- | --- |
| ชื่อ อย่างเดียว | `txtfind_type=2` | `firstName` |
| นามสกุล อย่างเดียว | `txtfind_type=3` | `lastName` |
| ทั้งสองช่อง | `type=2` และ `type=3` ขนานกัน | `both`, `firstName`, `lastName` |

กรณีกรอกทั้งสองช่อง ผลจากสองคำขอถูกรวมแล้วแบ่งกลุ่มด้วย `licenseNo` เป็นคีย์
แถวที่ปรากฏในทั้งสองผลคือกลุ่ม `both` (ตรงทั้งชื่อและนามสกุล) ที่เหลืออยู่ในกลุ่ม
ของตัวเอง — กลุ่ม `firstName` และ `lastName` มีไว้เผื่อผู้ใช้สะกดอีกช่องผิด ซึ่งเกิด
ได้ง่ายเพราะต้นทางจับคู่แบบตรงตัว

### รูปแบบผลลัพธ์

```json
{
  "success": true,
  "query": { "firstName": "สมชาย", "lastName": "กีรติบูรณะ" },
  "counts": { "both": 1, "firstName": 71, "lastName": 1 },
  "groups": {
    "both": [
      {
        "title": "ภก.",
        "firstName": "สมชาย",
        "lastName": "กีรติบูรณะ",
        "fullName": "ภก. สมชาย กีรติบูรณะ",
        "licenseNo": "19383",
        "status": "ปกติ",
        "expiry": "26/04/2573",
        "notes": ["ใบอนุญาตเป็นผู้ประกอบวิชาชีพเภสัชกรรม ไม่เคยขอใบแทน"]
      }
    ],
    "firstName": [],
    "lastName": []
  }
}
```

`counts` นับจำนวนก่อนตัด ไม่ใช่ความยาวของอาร์เรย์ที่ส่งกลับ (ดูหัวข้อขีดจำกัด)

### การแปลง HTML

หาตารางที่มี `bordercolor="#66CC66"` แล้วอ่านทีละแถว ข้ามแถวหัวตาราง

- คอลัมน์ชื่อมีคำนำหน้า ชื่อ นามสกุล ในสตริงเดียว ตามด้วย `<br/>` และหมายเหตุ
  ตัดคำนำหน้า (`ภก.` หรือ `ภญ.`) ออกเป็น `title` ที่เหลือ split ด้วยช่องว่างแรก
  เป็น `firstName` และ `lastName` — นามสกุลไทยไม่มีช่องว่างในตัว
- `notes` เก็บข้อความในแท็ก `<span>` ที่มีสี ทั้งบรรทัดสีน้ำเงิน (เรื่องใบแทน) และ
  บรรทัดสีแดง (เช่น "หน่วยกิตการศึกษาต่อเนื่องไม่เป็นไปตามหลักเกณฑ์") ตัดขีดนำ
  หน้าและช่องว่างส่วนเกินออก
- แถวเดียวที่มี `colspan` และข้อความ "ไม่พบรายการ" แปลว่าไม่เจอ คืนอาร์เรย์ว่าง
- `expiry` ที่เป็น `-` แปลงเป็นสตริงว่าง

ใช้ regex ไม่ใช้ไลบรารี parse HTML — โครงตารางคงที่และแอปนี้ไม่มี dependency
สำหรับงานนี้อยู่แล้ว

### แคช

คีย์คือ `firstName|lastName` เก็บทั้งผลลัพธ์ที่รวมกลุ่มแล้ว ใช้ `CACHE_TTL_MS`
(30 นาที) และ `CACHE_MAX` (50 รายการ) ที่มีอยู่ ตัวที่ใช้นานสุดถูกไล่ออกก่อน
แคชแยกจากแคชของ `scraper.js` และ `DELETE /api/cache` ที่มีอยู่ให้ล้างทั้งสองตัว

### ขีดจำกัดและข้อผิดพลาด

เก็บสูงสุด 200 แถวต่อหนึ่งกลุ่ม — "สมชาย" คืน 71 แถว ชื่อที่พบบ่อยกว่านั้นอาจมากกว่า
และ panel ในหน้าจอไม่ได้ตั้งใจให้ไล่อ่านเป็นร้อย ๆ `counts` ยังรายงานจำนวนเต็ม
เพื่อให้ UI บอกได้ว่าถูกตัด

| กรณี | สถานะ | รหัส |
| --- | --- | --- |
| ไม่ส่งคำค้นมาเลย | 400 | `MISSING_QUERY` |
| ต้นทางล่ม หรือเกิน `NAV_TIMEOUT_MS` | 502 | `UPSTREAM_ERROR` |
| หาตารางผลลัพธ์ไม่เจอ | 502 | `PARSE_ERROR` |
| ค้นแล้วไม่เจอรายชื่อ | 200 | — (กลุ่มว่าง) |

`PARSE_ERROR` มีข้อความ "โครงสร้างหน้าเว็บสภาเภสัชกรรมเปลี่ยน กรุณาแจ้งผู้ดูแล
ระบบ" — เมื่อสภาเภสัชกรรมแก้ template ต้องเห็นความผิดพลาดชัดเจน ไม่ใช่เข้าใจผิด
ว่าไม่มีเภสัชกรคนนั้น

## Frontend

### component

`<pharmacist-search>` — custom element ไฟล์เดียว ไม่มี dependency

โครงหน้าตา

```
┌ ค้นเลข ภ. ─────────────────┐
│ [ชื่อ            ]         │
│ [นามสกุล         ] [ค้นหา] │
├────────────────────────────┤
│ ตรงทั้งชื่อและนามสกุล (1)   │
│   ภก. สมชาย กีรติบูรณะ      │
│   ภ. 19383      [คัดลอก]   │
│   ปกติ · หมดอายุ 26/04/2573 │
│   หน่วยกิตไม่เป็นไปตาม…     │
├────────────────────────────┤
│ ตรงเฉพาะชื่อ (71)        ▸ │
│ ตรงเฉพาะนามสกุล (1)      ▸ │
└────────────────────────────┘
```

พฤติกรรม

- ค้นเมื่อกด Enter หรือกดปุ่มค้นหาเท่านั้น ไม่ค้นระหว่างพิมพ์ — ต้นทางจับคู่แบบ
  ตรงตัว คำที่พิมพ์ยังไม่จบจึงไม่มีวันเจอ การยิงถี่ ๆ ได้แต่ผลว่าง
- ใช้ `AbortController` ยกเลิกคำขอเดิมเมื่อยิงคำขอใหม่ ตามแบบ `web/src/api.js`
- กรอกช่องเดียว ผลมีกลุ่มเดียว แสดงเป็นรายการเรียบ ไม่มีหัวข้อกลุ่ม
- กรอกสองช่อง กลุ่ม `both` กางอยู่แล้ว อีกสองกลุ่มพับไว้พร้อมจำนวนในวงเล็บ กด
  หัวข้อเพื่อกาง
- ปุ่มคัดลอกส่งเฉพาะตัวเลขใบอนุญาตลง clipboard ผ่าน `navigator.clipboard` แล้ว
  ขึ้นข้อความ "คัดลอกแล้ว" 1.5 วินาที
- ถ้าจำนวนใน `counts` มากกว่าจำนวนแถวที่ได้ ท้ายกลุ่มขึ้นบรรทัด "แสดง 200 จาก
  N รายการ — ระบุอีกช่องเพื่อจำกัดผล"
- สถานะระหว่างทาง: กำลังค้น (spinner), ไม่พบ ("ไม่พบรายชื่อ — ต้องสะกดชื่อและ
  นามสกุลให้ตรงทุกตัวอักษร"), ผิดพลาด (ข้อความจาก API ด้วยสี `--destructive`)
- panel ผลลัพธ์มี `max-height` และ scroll ในตัว ไม่ดันเลย์เอาต์ของหน้า

### จุดที่วาง

**Sidebar (`web/src/components/Sidebar.jsx`)** — วาง `<pharmacist-search />` ใต้
รายการเมนู คั่นด้วย `<hr>` เหนือส่วน `.foot` โหลดสคริปต์ด้วย `<script src="/pharmacist-search.js">`
ใน `web/index.html` React 19 ส่ง attribute ให้ custom element ได้ตรง ๆ จึงไม่ต้อง
มี wrapper

**หน้าบันทึกการตรวจ (`web/public/form.html`)** — วางบนสุดของหน้า เหนือหัวเอกสาร
เป็นกล่อง glass เพิ่ม `<script src="./pharmacist-search.js">` และกฎ
`@media print { pharmacist-search { display: none } }`

หน้านี้ถูก Puppeteer โหลดตอน render PDF ด้วย component จะถูกสร้างแต่ไม่ยิง API
ถ้าไม่มีคนกดค้นหา และถูกซ่อนด้วย print CSS จึงไม่ปรากฏใน PDF หรือ DOCX

### CSS

ต่อท้าย `web/public/theme.css` ประมาณ 40 บรรทัด ใช้ token ที่มีอยู่: `--glass`,
`--glass-border`, `--radius`, `--primary`, `--muted-foreground`, `--destructive`,
`--ok-bg`/`--ok-fg` สำหรับป้ายสถานะ และ `--danger-bg`/`--danger-fg` สำหรับหมายเหตุ

## การทดสอบ

สองระดับ ใช้ `assert` ของ Node ล้วน ตามแบบที่โปรเจกต์ทำอยู่ ไม่มี test framework

**`test-parse.js`** — ตรวจตัวแปลง HTML กับไฟล์ที่บันทึกไว้ ไม่ต้องต่อเน็ต
fixture คือหน้าจริงสามหน้า: ผลค้นนามสกุลที่มีหลายรายการ ผลที่มีหมายเหตุสีแดง และ
หน้า "ไม่พบรายการ" ตรวจว่า

- แยกคำนำหน้า ชื่อ นามสกุล ถูกต้องทั้ง `ภก.` และ `ภญ.`
- `licenseNo` เป็นตัวเลขล้วน และคงเลขศูนย์นำหน้าไว้ (เช่น `07808`)
- `notes` เก็บทั้งบรรทัดสีน้ำเงินและสีแดง
- `expiry` ที่เป็น `-` กลายเป็นสตริงว่าง
- หน้าไม่พบรายการคืนอาร์เรย์ว่าง ไม่ throw
- HTML ที่ไม่มีตารางผลลัพธ์ throw `PARSE_ERROR`

**`smoke-pharmacist.js`** (`npm run smoke:pharmacist`) — ยิงต้นทางจริง แบบเดียว
กับ `smoke.js` นี่คือกันดักหลัก เมื่อสภาเภสัชกรรมแก้หน้าเว็บ สคริปต์นี้ต้องแดง
ตรวจว่า

- ค้นนามสกุลที่รู้ว่ามีอยู่ ได้อย่างน้อยหนึ่งแถว มี `licenseNo`, `fullName`, `status`
- ค้นชื่อและนามสกุลของคนเดียวกันพร้อมกัน กลุ่ม `both` มีอย่างน้อยหนึ่งแถว และ
  `counts.firstName` มากกว่า `counts.both`
- ค้นคำที่ไม่มีอยู่จริง ได้กลุ่มว่างทุกกลุ่ม ไม่ throw
- ยิงซ้ำคำเดิมได้ผลจากแคช (เร็วกว่าครั้งแรกอย่างชัดเจน)

ฝั่ง UI ตรวจด้วยมือ: หน้า search page เปิด sidebar ค้นแล้วคัดลอกเลขได้
หน้า form.html ค้นได้และสั่งพิมพ์แล้ว widget ไม่ติดไปในหน้ากระดาษ และ
`POST /api/form/pdf` ยังได้ PDF หน้าตาเดิม
